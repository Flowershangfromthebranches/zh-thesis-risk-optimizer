# 计算机/软件工程策略提示词

## 改写规则

1. 不要写百科式技术介绍
2. 必须解释"本文系统中该技术具体怎么用"、"为什么选这个技术而不是其他"、"版本和配置是什么"
3. 不要在背景段落写宏大叙事（"随着互联网的发展……"）
4. 多写系统真实实现过程

## 实现章节（最优先）

- 增加核心函数逻辑、关键代码段说明、异常处理方式、界面交互描述
- 不要只写"实现了某模块"，要写具体实现方法
- 写上开发环境、依赖库版本、接口路径、数据库表结构

## 测试章节

- 增加测试环境配置（OS/硬件/依赖版本）
- 测试步骤、测试用例表格
- 预期结果 vs 实际结果
- 发现的问题和修复过程
- 人工复核情况、测试局限性

## 系统设计章节

- 重点写模块关系、数据流、输入输出
- 增加设计取舍说明——为什么这样设计，有哪些替代方案
- 保留图表，但要用文字补充设计逻辑

## 禁止

- 不要写空泛结论（"具有良好的稳定性和实用性"）
- 不要把代码逻辑写成散文
- 不要只写概念不写实现
